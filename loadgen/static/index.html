새 타겟 직접 등록

1. Schema (대상 스키마 조회)

스키마만 있고 데이터는 빈 DB를 미리 준비해 둘 것 — DB 생성과 스키마 적용은 이 도구가 하지 않는다.

2. Seed Plan (시딩 플랜)

테이블별 행수는 스키마 구조로 추정한다 (추천값 — 아래 표에서 수정 가능).
시딩 후 양쪽 데이터 대조

3. Workload (트랜잭션 믹스)

스키마의 PK·FK·인덱스로 초안을 만든다. 실제 쿼리 패턴은 스키마만으로 알 수 없으므로 반드시 검토할 것.
검증은 각 SQL을 한 번씩 실행한다. 쓰기는 롤백하므로 데이터를 건드리지 않는다. 0행 조회는 에러가 아니어서 부하 중에는 잡히지 않으므로 여기서 확인하는 것이 유일한 방법이다.
